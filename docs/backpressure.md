# Backpressure demo (#3)

Generated by `scripts/bench_backpressure.py`. The producer emits items with zero per-item latency; the consumer sleeps `--consumer-ms` per item. `stream`'s bounded `asyncio.Queue` applies backpressure when the consumer can't keep up.

## OOM-safety claim

`max_queue_depth` is bounded by `queue_size` in every row above (3 rows, queue_size [8, 32], n [500, 5000]). That bounds the input *waiting to be processed*: a fast producer cannot pile items up ahead of a slow consumer, at any `n`.

That is a bound on the input side, not on the process: `stream` returns every result in one list, so results are O(n) and `stream` is not safe on a source that never ends -- it never returns. In this table, at `queue_size` 8, `peak_heap_kb` goes 21.4 → 202.7 (9.5×) as `n` goes 500 → 5000 (10.0×).

The rows span more than one `n` ([500, 5000]) at a fixed `queue_size`, which is what makes this table evidence for the `n`-independence of the bound rather than only for its value at one workload size. The general claim is proved where it belongs, over a parameterised table in `tests/test_stream.py` -- `test_stream_metrics_max_depth_bounded_by_queue_size` -- which is host-independent; this table is the measured illustration.
